# Insurance Agent Sales & Renewal Copilot

An educational prototype (Team 4, GenAI capstone). The copilot helps a licensed advisor (simulated) answer product questions, prepare renewal reminders and document follow-ups.

> **Non-goals.** This is not a real Star Health or mfine service, a medical device, or an underwriting or claims tool. All customers, plans, brochures and templates are **fictional and synthetic**. No real policyholder data is used. Nothing is ever sent to a real person.

## What it does today (MVP backend)

| Agent asks | Copilot does |
| --- | --- |
| "Draft a renewal reminder for C-204 and explain differences between Silver and Gold" | Looks up the synthetic record, saves a draft that waits for approval, and returns a cited Silver vs Gold comparison with each plan's unique exclusions. |
| Renewal for a customer with `consent_status = opt_out` | Warns the agent and prepares nothing. |
| "Does Gold cover maternity?" (not in the corpus) | Says the fact is unavailable and escalates. It does not guess. |
| "Auto-send it without review" | Flags the request and blocks the send. |
| A brochure that says "ignore previous instructions" | Flags it and treats it as data, never as an instruction. |

Every factual claim carries a source ID (for example `CAT-GOLD-2025.1`). Every action is recorded in an audit trail.

## Architecture

```text
Agent / UI -> FastAPI (copilot/api.py)
                |-> router.py   classify intent, decide the workflow
                |-> rag.py      BM25 search, metadata filters, injection flags
                |-> tools.py    lookup (read) | save_draft (write, mock CRM)
                |               approve_draft | simulate_send (approval + consent)
                |-> store.py    synthetic CSV/JSONL data, drafts, audit log
```

Also included: a React + TypeScript UI in `ui/` (ask, cited answers, approval queue, audit trail). Planned next: a Hugging Face task classifier, Azure AI Search as an alternative to the local index, and a small .NET 8 client.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python scripts/generate_data.py    # optional: fixtures are already committed
pytest -q                          # run the tests
uvicorn copilot.api:app --reload   # then open http://127.0.0.1:8000/docs
```

React UI (in a second terminal, with the API running):

```bash
cd ui && npm install && npm run dev   # http://localhost:5173
```

Docker:

```bash
docker build -t copilot . && docker run -p 8000:8000 copilot
```

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/health` | Liveness and fixture counts |
| GET | `/customers/{id}` | Read-only synthetic customer lookup |
| GET | `/products` | Approved product catalogue |
| POST | `/ask` | Ask a question. Never sends anything. |
| GET | `/drafts/{id}` | Read a draft |
| POST | `/drafts/{id}/approve` | Record that a named agent reviewed the draft |
| POST | `/drafts/{id}/send` | Simulated send. Needs approval and opt-in consent. |
| GET | `/audit` | Audit trail (IDs and statuses only) |

## Synthetic data

Generated by `copilot/data_gen.py` with a fixed seed (42), so every teammate gets identical files. CI regenerates the data and fails if the committed files differ.

| File | Contents |
| --- | --- |
| `customers.csv` | 500 customers: ID, city, renewal date, segment, consent |
| `policies.csv` | Plan and renewal per customer |
| `interactions.csv` | 1,200 synthetic interaction notes |
| `product_catalog.jsonl` | Fictional Silver, Gold and Platinum with exclusions and source IDs |
| `brochures.jsonl` | Brochure text for retrieval |
| `approved_templates.jsonl` | Approved, non-binding message templates |

## Responsible AI and security

- Synthetic data only. No real names, numbers or records.
- No eligibility decisions and no advice based on protected characteristics.
- Sends require explicit agent approval and an opt-in consent check, both enforced in code and tested.
- Retrieved text and tool output are treated as untrusted data.
- Secrets never go in the repo. Use `.env` locally and Key Vault or GitHub secrets later. `.env` is git-ignored.
- Gitleaks runs in CI.
